# kb-game

Prodigy game knowledge base + procedural skill reference. Markdown corpus at the root, Dockerfile that bakes a [qmd](https://github.com/tobi/qmd)-backed local hybrid+rerank search index over it.

Scope: starts with Math Game; Game Island joins next. Shared across product, design, and data working on games.

> Want to use it from Claude Code? Jump to [Use the kb in Claude Code](#use-the-kb-in-claude-code).

## What's here

```
kb-game/
├── knowledge/                  ← factual reference (event schemas, design, profiles)
│   ├── event-schemas/
│   ├── game-design/
│   ├── session-profiles/
│   ├── INDEX.md                ← regenerated by build_index.py
│   └── pages.json              ← regenerated by build_index.py
│
├── skills/                     ← procedural workflows (DDD drafting, GDD drafting, …)
│   └── ddd-drafting/
│       ├── SKILL.md            ← entry prompt
│       ├── reference/          ← templates, heuristics, examples (indexed)
│       ├── arcs/               ← per-execution observations (NOT indexed)
│       └── reviews/            ← weekly review notes (NOT indexed)
│
├── tools/
│   └── build_index.py          ← regenerates knowledge/INDEX.md + pages.json
│
├── tests/
│   └── mcp-smoke.sh            ← smokes the image's stdio MCP surface
│
├── Dockerfile                  ← multi-stage qmd build
├── README.md                   ← this file
└── CLAUDE.md                   ← layout contract + repo-internal guidance
```

The corpus is two trees:

- **`knowledge/`** — slow-changing factual reference, PR-reviewed. Indexed as the `kb` collection.
- **`skills/<name>/reference/`** — procedural craft for a workflow. One collection per skill (`skill-<name>`). Evolves weekly via the arcs → review → PR loop (see CLAUDE.md).

Arcs and reviews are intentionally excluded from indexes — they are proposals, not truth.

## The image

```sh
docker build -t kb-game:dev .
docker run --rm kb-game:dev --version                       # qmd 2.1.0
docker run --rm kb-game:dev query "progression event schema"            # hybrid + rerank
docker run --rm kb-game:dev query "DDD section ordering" -c skill-ddd-drafting
docker run --rm kb-game:dev search "session_id"                          # BM25 only
docker run --rm kb-game:dev vsearch "core gameplay loop"                 # vector only
docker run --rm kb-game:dev status                                       # health + collections
docker run --rm -i kb-game:dev mcp                                       # stdio MCP server
```

Use `-c <collection>` to scope a query. Without `-c`, qmd searches all registered collections.

### Pinned versions

| | |
|---|---|
| qmd | `2.1.0` (`@tobilu/qmd`) |
| Embedding model | `hf:ggml-org/embeddinggemma-300M-GGUF/embeddinggemma-300M-Q8_0.gguf` |
| Reranker model | `hf:ggml-org/Qwen3-Reranker-0.6B-Q8_0-GGUF` |
| Query-expansion model | `hf:tobil/qmd-query-expansion-1.7B-gguf` |
| Node runtime | `22.14.0` (Debian bookworm-slim base) |

Bumping qmd or any model is a breaking change for anyone holding an older index — qmd refuses to query an `index.sqlite` produced by a different model.

### Build characteristics

- **First local build:** ~30+ min on a 4-core CPU-only VM. Most of the time is the embedding pass over `knowledge/` + `skills/*/reference/`.
- **Doc edit rebuild:** any change under `knowledge/` or any skill's `reference/` invalidates the index stage and re-runs the full embed.
- **No-change rebuild:** seconds — all stages hit cache.
- **Doc-only edits do NOT re-download model weights** — the `model` stage stays cached.
- **Adding a new skill:** drop a directory under `skills/<name>/reference/`. The Dockerfile's index stage discovers it via shell glob; no Dockerfile edit needed.

### Known gotchas

- **CPU embed flakiness.** `qmd embed` on CPU occasionally drops chunks with "Session expired — skipping". Mitigated via `--max-docs-per-batch 30` plus a second retry pass in the Dockerfile.
- **Apple Silicon rerank latency.** Under colima/Docker, the rerank model on CPU can take 1–3 min per query. Pass `rerank: false` for interactive use; turn rerank on for batch authoring where minutes are acceptable.

## Use the kb in Claude Code

The image's default `CMD` is qmd's stdio MCP server, so `docker run -i <image>` is a drop-in transport for Claude Code.

### 1. Build the image locally

```sh
cd /path/to/kb-game
docker build -t kb-game:dev .
```

### 2. Wire it into `~/.claude/mcp.json`

```jsonc
{
  "mcpServers": {
    "kb-game": {
      "command": "docker",
      "args": ["run", "--rm", "-i", "kb-game:dev"]
    }
  }
}
```

Restart Claude Code. The `query` / `get` / `multi_get` / `status` tools appear under the `kb-game` server in `/mcp`.

### Tools exposed

qmd's MCP server exposes four tools over stdio:

| Tool | Purpose |
|---|---|
| `query` | Hybrid search with typed sub-queries (`lex` / `vec` / `hyde`) + LLM rerank. Best for general use. |
| `get` | Fetch a single document by file path or `#docid` from a search result. |
| `multi_get` | Batch-fetch documents by glob (`event-schemas/*.md`) or comma-separated list. |
| `status` | Index health (collections, document counts, model versions). |

Set `rerank: false` on the `query` tool when running on CPU-only machines — skipping the rerank model cuts latency from minutes to seconds at some quality cost.

Use the `collection` parameter to scope: `query("…", collection: "kb")` or `query("…", collection: "skill-ddd-drafting")`.

### Smoke test

```sh
tests/mcp-smoke.sh                  # against kb-game:dev
tests/mcp-smoke.sh kb-game:<sha>    # against a tagged image
```

Asserts the server identifies as `qmd` and exposes the four expected tools.

## Editing the kb

- Hand-edits to `knowledge/**/*.md` and `skills/*/reference/**/*.md` are the norm. Open a PR.
- After any edit that changes a `title`, `last_modified`, or moves a file, rerun `uv run tools/build_index.py` to refresh `knowledge/INDEX.md` and `knowledge/pages.json`.
- Adding a new skill: `mkdir -p skills/<name>/{reference,arcs,reviews}` plus a `SKILL.md` and at least one file under `reference/`. The Dockerfile picks it up automatically on next build.

See `CLAUDE.md` for the frontmatter contract and the arc/review lifecycle.
